# ADR-001 — API-first modular monolith and transactional order processing

Date: 2026-10-24
Status: **Partially approved — architecture direction only**
Decision owner: Human Technical Owner
References: ORDER_INVENTORY_KICKOFF.md, ARCHITECT_REVIEW_001.md

## Approved decisions
- **Architecture:** NestJS modular monolith, MySQL InnoDB for transactional data.
- **Delivery:** API-only for milestone 1; Angular is deferred.
- **Persistence access:** TypeORM; version and exact transaction facilities to verify when implementing.
- **Authentication:** JWT with seeded demo users. Object-level authorization required.
- **Order model:** multiple line items per order.

These approvals **do not authorize application-code implementation, dependency installation, schema migration, merge, or deployment**.

## Context
The project is a training system to learn technical planning, authorization, transaction isolation, concurrency and evidence-based AI code reviews. The main correctness invariants are no overselling, no duplicate confirmed order on retried requests and no partial committed stock deduction.

## Alternatives
1. **Modular monolith + MySQL (approved direction):** simpler atomic transactions, local testing and debugging, less operational overhead. Trade-off: shared deployment and need for careful module boundaries.
2. **Split Orders and Inventory services (not selected):** independent scaling/deployment, but requires distributed messaging/compensation and more failure modes without demonstrated need.

## Proposed module boundaries
Auth handles identity and claims. Catalog owns product data and price/active rules. Inventory owns stock mutation invariants. Orders orchestrates a single database transaction and idempotency; ownership checks govern reads. Modules share the MySQL transaction manager within the process; avoid cyclical imports and business logic in controllers.

## Architecture consequences
- One relational database can commit order, order lines, stock updates and idempotency record atomically.
- Prefer deterministic transactional ordering; no Redis, queue, MongoDB or microservices in milestone 1.
- Price/stock concurrent edit policy, retention/idempotency semantics, status codes and money limits are **proposals** pending human acceptance.
